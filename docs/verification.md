## 環境與重現方式

- Windows；CPython 3.13.5（使用本機 Miniconda 的 Python 建立獨立 venv）。
- PATH 原本指向 MSYS2 Python 3.12.12，缺少 pip。測試改使用專案內 `.venv/windows`，未修改全域 Python。
- 安裝 `requirements.txt`、執行 editable install 成功；`pip check` 無相依衝突。
- 實際套件版本已保存於 `requirements-lock.txt`，包含開發工具。

在本次已建立的環境中執行：

```powershell
.\.venv\windows\Scripts\python.exe -m pytest -q
.\.venv\windows\Scripts\thsr-ticket.exe --help
.\.venv\windows\Scripts\thsr-ticket.exe
```

最後一個指令會開始互動訂票；本次只測試 `--help` 與離線模擬，沒有送出真實訂單。

## 已修復與驗證

- TinyDB 目錄改用作業系統路徑處理；測試涵蓋 Windows 巢狀路徑、單一檔名、讀寫及重複紀錄。
- 選單輸入拒絕非整數與超出範圍的數字；日期不能早於今天，起訖站不能相同，總票數限制 1–10。
- 補上票種、車廂、座位偏好輸入；座位選項由頁面讀取。
- 新增手機與身分證格式檢查；證號檢查僅驗證格式，沒有驗證檢查碼。
- 表單 action 與 hidden fields 從目前回應讀取，送出資料放在 POST body。
- HTTP 加入 timeout、HTTP 狀態檢查及來源網址限制；不自動重送 POST。
- 修正車次與錯誤解析器重複使用時累積舊資料；缺少預期頁面元素時提供錯誤提示。
- 查詢錯誤後可重新查詢取得新驗證碼；選車輸入 0 可重新設定條件。
- 訂票送出後，若連線失敗或結果無法解析，提醒先至官網確認，不自動重訂。
- 保存個人資料改為訂票完成後自行選擇，預設不保存；歷史列表遮蔽證號與手機。
- 舊測試修正過時的欄位預期，並改用獨立 fixture，避免依賴執行順序。

## 尚待確認與技術欠項

1. **網站相容性尚未確認**：首頁未能取得，無法驗證現行表單 action、欄位、驗證碼、可訂日期及後續頁面。
   需在可連線的環境先跑 `--live`，再由使用者手動輸入驗證碼驗證查詢及選車。
   本次未實際付款、訂票或取消訂位。
2. **全專案靜態檢查仍未通過**：mypy 設定指定 Python 3.8，但本次安裝的 mypy 已不支援此目標；
   原始執行方式也受根目錄 `__init__.py` 與含連字號的專案名稱影響。
   使用 `--explicit-package-bases -p thsr_ticket` 檢查仍有型別問題，包含 Pydantic alias 判讀、
   BeautifulSoup 型別、未標註的驗證器與測試，以及 `ml/` 缺少的實驗套件。
   Pylint 也仍有命名、舊寫法與介面參數命名等診斷。沒有放寬既有檢查來宣稱全數通過。
3. **CI 尚未現代化**：原有 GitHub Actions 使用 Python 3.8 及舊版 actions，未在遠端執行。
   後續需決定支援的 Python 版本，整理正式程式、測試與 ML 實驗的依賴／檢查範圍，再更新 CI。
4. **歷史資料仍是明文**：本次加入保存選擇及畫面遮蔽，未宣稱加密，也未刪除既有資料。
5. **功能界線**：目前為單程、依時間查詢。直接指定車次、只看早鳥、會員、護照及其他 README 未完成功能仍待開發。
   `ml/` 未接入訂票流程，本次未安裝或執行其影像辨識實驗。

下一個實作優先順序：先取得實站頁面驗證，再處理靜態檢查與 CI；在這些項目完成前，不把離線成功當成可用的線上訂票保證。
