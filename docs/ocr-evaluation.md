# OCR 模型比較與評估

這次新增有限次換圖重試，以及可選的第二套 OCR 模型。**重試能處理偶發辨識失敗，但不等於單張圖片準確率提升。**
尚未取得足夠的人工標註高鐵圖片，沒有宣稱新模型的實站準確率較高，也沒有重新訓練模型。

## 使用另一套模型

[ddddocr 官方文件](https://github.com/sml2h3/ddddocr/blob/master/README.md) 提供 `beta=True` 切換第二套內建模型。
已核對本機 1.6.1 程式：預設載入 `common_old.onnx`，beta 載入 `common.onnx`；名稱不同不代表對高鐵圖片一定更準。

在 `booking.local.json` 中加入或修改：

```json
"ocr_model": "beta"
```

此行需放在原本 JSON 物件內，與相鄰欄位用逗號分隔。填 `"standard"` 可回到原模型，省略欄位也使用 standard。
兩種模式都在本機推論、提前載入、重用模型，保留四碼英數字篩選與每碼最低分數 0.5 門檻。
不會降低門檻硬猜，也不會依同一張圖片依序向網站提交多組候選。

兩套模型已在本機成功載入，並辨識同一張人工產生的 A7B3 測試圖片；這只驗證套件與解碼相容性，不是高鐵準確率評測。

## 用自己的人工標註圖片比較

提供純離線工具，同一批圖片依序測試兩套模型，不連線、不訂位，也不修改設定檔。
圖片需有獨立核對的正確文字；不要把 OCR 自己猜的文字當成標籤。錯誤查詢只表示答案錯了，不提供真正答案。

可將圖片和 `labels.json` 放在已忽略的 `.venv/ocr-evaluation/` 中。標註格式如下（圖片需自行準備）：

```json
[
  {"image": "sample-001.png", "label": "A7B3"},
  {"image": "sample-002.png", "label": "Z9X2"}
]
```

圖片路徑相對於標註檔所在資料夾。上述只有格式示範，不是可代表實站的樣本集。

```powershell
.\.venv\windows\Scripts\python.exe -m thsr_ticket.ocr_benchmark .venv/ocr-evaluation/labels.json
```

輸出各模型的整體統計，不列出圖片內容或逐張標籤：

| 指標 | 意義 |
| --- | --- |
| `samples` | 圖片數量 |
| `correct` / `wrong` / `abstained` | 全碼正確、全碼錯誤、不接受辨識結果的張數 |
| `exact_match_rate` | 全碼正確張數 ÷ 全部圖片數；不是逐字元正確率 |
| `coverage` | 願意輸出候選的圖片比例 |
| `accepted_accuracy` | 全碼正確張數 ÷ 輸出候選張數；完全不輸出候選時為 null |
| `mean_inference_ms` | 平均單張辨識耗時，不含模型載入、網路或訂位時間；第一張推論仍可能有暖機成本 |

工具亦接受 `--min-score` 比較門檻，但不會將此實驗設定套用至訂票程式。
模型載入或推論故障會讓評估失敗，不會把故障混成低準確率。

## 後續改善依據

先收集具代表性且人工核對的圖片，以整張正確率、錯誤候選數與耗時一起比較，
再決定是否改用 beta、調整門檻或測試圖像處理；目前不直接上線未驗證的二值化、去線或強制字元替換。
若兩套通用模型都不足，再考慮專用模型訓練。用來選模型或調參的圖片與最後驗證的圖片應分開，
避免同一批資料反覆調參後高估準確率。
