# 紀錄版本與歷史整理

此功能位於最新原始碼，尚未整合到既有 0.3.3 安裝包。

## GUI 操作

1. 停止任務，進入「設定 → 整理歷史紀錄」。
2. 背景掃描時顯示已檢查目錄數，可按「取消掃描」。取消不會移動紀錄。
3. 在「執行紀錄」輸入起迄日期（YYYY-MM-DD，可留空）後按「篩選」。日期依事件檔最後修改時間，以台灣時間顯示，並非乘車日期。
4. 逐筆勾選或按「全選篩選結果」，檢查已選筆數與容量，再按「整理所選」並確認。套用篩選會清除勾選，避免整理隱藏項目。
5. 在「備份批次」選擇要還原的批次，按「還原此批次」並確認；重開程式後仍可掃描所有備份。操作完成後按「重新掃描」更新列表。
6. 若啟動或載入設定後出現「中斷復原」，先檢查批次，再按「回復操作前位置」並確認。程式不會因偵測到中斷而自動移動資料。

掃描、雜湊驗證、移動與還原都由背景執行緒處理。處理期間不允許載入設定或啟動訂位；關閉程式會先取消掃描，或等待已開始的移動／還原完成。只有掃描可取消，避免在檔案移動途中強制停止。

備份位於設定旁的 `*.runs.history-backups/<批次識別碼>/`。整理是移動，不是永久刪除，因此不會釋放磁碟空間。它不修改官網訂位、不刪除設定、防重送狀態或封存狀態。部分訂位仍可能從封存狀態顯示簡略資訊。

只處理 UUID 名稱的執行目錄，且只能含 `events.jsonl`、`result.json`。最後一筆事件必須為 `run_finished` 或 `run_stopped`。未完成、損壞、未知版本、額外檔案、符號連結或 Windows junction 均不整理。任何目前訂位狀態存在時，包含損壞的狀態，都先要求人工核對。

預覽保存各檔內容雜湊；確認時取得與訂位相同的跨程序鎖，再重新比較所選紀錄。所選紀錄變更會要求重新預覽；未選紀錄不移動。移動出錯會嘗試移回已移動的目錄；若檔案系統持續失敗，請保留原位置與備份，勿自行覆寫。還原遇到同名紀錄會拒絕覆寫。

## 中斷復原與錯誤指引（2026-10-22）

每次整理／還原都在設定旁的 `*.runs.operations/<操作識別碼>.json` 保存操作清單。它包含版本、方向、備份批次、時間、紀錄目錄識別碼、位元組數及 SHA-256，不保存設定、證號、訂位代碼或原始錯誤文字。請連同原紀錄及備份保管，勿自行刪除尚未處理的清單。

操作清單先以 `pending` 狀態原子寫入並 fsync，才開始移動目錄；全批完成後寫入 `complete`。一般例外會先嘗試回復；若連回復也失敗，清單仍保持待處理，介面提示 `rollback_failed`。強制結束程序不會執行例外處理，因此下一次啟動會重新檢查未完成清單。

「回復操作前位置」與「備份批次 → 還原此批次」的用途不同：整理中斷會把該批次移回執行紀錄區；還原中斷會把該批次移回原備份區。復原時整批先檢查，再逐筆回移，不重送任何訂位。復原成功標示 `rolled_back`，重複確認不會再次移動。

| 每筆紀錄的實際狀況 | 處理方式 |
| --- | --- |
| 只在操作前位置，內容符合清單 | 保留原位置。 |
| 只在移動後位置，內容符合清單 | 回移到操作前位置。 |
| 兩側同名、兩側都不存在、內容或結構變更 | 整批預檢停止，保留資料，顯示 `recovery_conflict`。 |
| 清單損壞或版本不支援 | 唯讀顯示，停用自動復原，提示保留資料及尋求人工協助。 |

待復原期間會阻擋新的整理與普通批次還原，也不會把中斷批次當成完整備份。中斷前沒有操作清單的舊版操作無法回溯推斷；此機制不能重建已遺失的內容，也不代表能保證磁碟硬體故障或斷電時所有檔案系統寫入都已落盤。

| 常見錯誤 | 介面指引 |
| --- | --- |
| `permission_denied` | 關閉占用程式、確認資料夾權限，重新掃描。 |
| `operation_busy` | 停止另一個訂位或紀錄工作並等待結束。 |
| `records_changed` | 重新掃描並勾選。 |
| `restore_conflict` | 保留兩側資料，確認重複紀錄，避免覆寫。 |
| `recovery_required`／`rollback_failed` | 排除權限或占用問題後，進入「中斷復原」。 |
| `disk_full` | 釋放其他檔案空間，保留訂位資料與備份。 |

未知錯誤採固定訊息，不直接顯示原始例外及私人路徑。若原位置或操作清單無法存取，請先排除權限問題；重新掃描後才可能列出待復原項目。

## 格式契約

新增的訂位狀態、完整結果、人工核對結果及執行事件都寫入 `_record_version: 1`。沒有版本欄位的舊紀錄仍可唯讀載入，不自動改寫，因此不會因讀取而改變舊防重送狀態。

`record_schema.py` 統一檢查 JSON 物件與版本；未知版本、字串、布林或 null 版本均拒絕。`booking_records.read_object` 用於訂位顯示與封存時執行此檢查。對於無法讀取的狀態，保留防重送檔，不以空狀態取代。

這是版本 1 的相容契約，沒有虛構版本 2 的轉換規則，也不會猜測或自動修補損壞的訂位內容。歷史整理備份可透過介面還原；損壞的目前訂位仍需人工核對。保留期限、永久刪除及跨 Windows 帳號的 DPAPI 復原不在本次功能範圍。

## 程式導覽

- `record_schema.py`：紀錄物件與版本驗證。
- `record_storage.py`：候選盤點、內容雜湊、鎖定後移動、最新備份搜尋與還原。
- `storage_journal.py`：移動前保存意圖、未完成批次偵測、內容預檢與可重入復原。
- `storage_errors.py`：固定錯誤分類與操作指引，不輸出原始例外文字。
- `desktop/controller.py`：預覽與操作狀態、設定切換防護、錯誤提示。
- `desktop/storage.py`：背景工作、進度與取消、日期篩選、勾選及備份批次模型；工作執行緒透過佇列回傳資料，由 Qt 計時器更新介面。
- `desktop/qml/Main.qml`：設定頁入口與確認對話框。
- `unittest/test_record_storage.py`：防重送、版本相容、原始內容保留與還原測試。
- `unittest/test_storage_recovery.py`：模擬程序中斷、回復再中斷、清單寫入失敗與衝突保護測試。
