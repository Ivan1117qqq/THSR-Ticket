# 完整備份與還原

雙鐵功能的台鐵設定、目前紀錄及封存資料位於 App 全域目錄，尚未納入此高鐵單份設定備份；位置與另行備份方式見 [雙鐵保存說明](dual-rail.md)。還原高鐵設定不會清除台鐵防重送紀錄。

2026-10-24 新增的常用行程範本、繳費提醒及一般偏好屬 App 全域資料，未納入這裡的單份設定封裝；全域檔案位置與另行備份方式見 [行程管理](journey-planner.md)。還原到新設定位置時，不自動套用原位置的手動提醒期限。

2026-10-23 原始碼更新。入口為「設定 → 資料管理 → 完整備份與還原」。本輪未製作安裝包，從原始碼啟動使用。

## 建立備份

1. 停止正在執行的任務或紀錄操作，先儲存目前行程設定。
2. 開啟「完整備份與還原」，在「建立備份」按「預覽目前資料」。讀取及 SHA-256 計算在背景進行，可取消預覽。
3. 檢查檔案數、容量、各類紀錄數量，以及是否有原防重送狀態。
4. 按「備份到新檔案」，選擇新的 `*.thsr-backup.zip` 檔名。既有檔案不覆寫；預覽後來源變更會要求重新預覽。

備份只包含磁碟上已儲存的資料，未儲存變更不會偷偷寫入設定。完整 ZIP **未整體加密**，含設定個資、訂位代碼、行程及原始紀錄，請妥善保管。它與已過濾個資的診斷匯出不同，不適合公開分享，也不會自動上傳。

## 還原備份

1. 切到「還原備份」，按「選擇備份檔」。程式會檢查結構、版本、大小、CRC 及每份內容的 SHA-256。
2. 按「選擇還原位置」，選擇父資料夾。程式會產生新的 `TravelDesk-Restored-<識別碼>` 子資料夾，並顯示完整目的位置及最新預覽。
3. 檢查防重送說明，再按「確認還原到新資料夾」。確認時會重新驗證備份與目的位置；既有資料夾即使為空也不合併或覆寫。
4. 成功後可按「開啟還原資料夾」。目前使用的設定不會自動切換，也不會啟動任務。
5. 核對原訂位後，可按「載入還原設定」。目前表單有未儲存變更時，請先返回儲存；載入仍須通過設定格式及 Windows 個資保護檢查。

還原檔名統一為新資料夾中的 `booking.local.json`，關聯資料使用同一個 basename。原檔內容及各檔修改時間會保留，避免歷史排序全部變成還原日期；目標檔案系統可能有時間精度差異。原始設定與記錄位置不會被改寫。

## 防重送規則

| 備份內容 | 還原後的行為 |
| --- | --- |
| 原本有已訂位或待確認狀態 | 完整保留原始狀態檔，不自動解除。 |
| 狀態損壞、版本未知或內容無法讀取 | 保留原始位元組，原有防重送阻擋仍在。 |
| 沒有狀態檔 | 新增 `_record_version: 1`、`submission_pending` 及 `restored_without_state: true` 的待核對狀態。必須經既有「我的訂位」官網核對流程處理後，才能訂下一筆。 |
| 任務摘要顯示前次仍在執行 | 摘要只供理解狀態，不會恢復排程或重送訂位。 |

舊備份沒有狀態檔，不能證明官網沒有既有訂位。還原也不會同步付款／取消狀態；目前開啟的原設定與還原設定各有關聯資料，請先核對再使用。

## 備份範圍

| 原位置 | 封裝內角色 | 還原後位置 |
| --- | --- | --- |
| 目前設定檔 | `config.json` | `booking.local.json` |
| 同名 `.state.json` | `state.json` | `booking.local.state.json` |
| 同名 `.task.json` | `task.json` | `booking.local.task.json` |
| 同名 `.runs/`，包含 `archives/` | `runs/` | `booking.local.runs/` |
| 同名 `.runs.history-backups/` | `history-backups/` | `booking.local.runs.history-backups/` |
| 同名 `.runs.operations/` | `operations/` | `booking.local.runs.operations/` |
| `<設定檔名>.config-backups/` | `config-backups/` | `booking.local.json.config-backups/` |

這是**單份行程設定及其關聯檔案**的完整備份，不包含其他設定、舊 CLI `.db`、瀏覽器資料、套件、EXE 或整個 App 使用者資料夾。桌面偏好也不匯入，避免把原電腦的 `last_config` 絕對路徑帶到目的電腦。空資料夾、作業鎖、檔案權限及其他檔案系統屬性不封裝。

各關聯目錄只接受一般 `.json`／`.jsonl` 檔案；額外不支援檔案、符號連結、junction 或無法讀取的檔案會使整次備份停止，不會靜默省略。紀錄內容本身可保留壞 JSON 或舊格式；完整性驗證不代表會修復或升級其內容。

每份最多 20,000 個檔案、總計 2 GiB，單檔最多 256 MiB，manifest 最多 8 MiB。超過限制時保留原資料並停止，不產生宣稱完整的部分備份。

## Windows 個資保護與搬移

備份與還原不解密、不重新加密，也不將受保護欄位轉成明文。還原到原 Windows 帳號及電腦環境後，仍應實際確認能載入；跨帳號或電腦搬移不能只靠此 ZIP 保證解密。

需要搬移時，先在原環境另行規畫可讀設定的匯出及目的環境重新保護。既有設定備份可能仍含明文個資；即使主要設定受保護，整份 ZIP 仍需妥善保管。載入失敗時，還原資料仍保留，目前設定及訂位狀態不會被切換或覆寫。

## 中斷與錯誤處理

預覽可以取消。開始寫入後不提供強制中止；關閉 App 會等待備份或還原完成，再處理未儲存提醒。處理期間會阻擋行程載入、儲存、新任務及紀錄修改。

備份先寫暫存 ZIP，驗證來源後以排他方式建立新目的檔案；一般失敗會清理自己建立的暫存／部分輸出，不刪除原先已存在或其他程序新增的檔案。程序被強制結束時可能留下不完整輸出，重新驗證失敗的 ZIP 請不要當作成功備份。

還原先排他建立新資料夾，寫入 `.travel-desk-restore-pending.json` 未完成標記。防重送狀態先寫、設定檔最後寫，全部檢查通過才移除標記。標記存在時設定讀取及儲存都會拒絕；中斷或錯誤時保留部分資料，請重新還原到另一個新資料夾，不要靠刪除標記或狀態檔放行。

測試使用故障注入模擬程序中斷，涵蓋寫入與讀取失敗、內容變更及目的位置競爭；這不是實際斷電或磁碟硬體故障保證。SHA-256 提供內容一致性檢查，不是備份來源的數位簽章。

## 程式與測試導覽

- `backup.py`：路徑及範圍檢查、來源盤點、封裝、manifest 驗證、逐檔雜湊、修改時間及安全還原。
- `desktop/backup.py`：背景工作、預覽與檔案選擇、取消、固定錯誤訊息及還原結果。
- `desktop/qml/BackupDialog.qml`：兩個分頁、摘要、目的位置、必要提醒及確認操作。
- `desktop/controller.py`：操作互斥、關閉等待、載入還原設定及防重送狀態刷新。
- `config_store.py`：未完成還原目錄的讀寫阻擋。
- `unittest/test_backup.py`：完整位元組／時間往返、無狀態時待核對、格式與路徑限制、競爭／失敗／中斷測試。
- `unittest/test_desktop.py`：GUI 流程、實際 QML 按鈕、操作互斥及關閉等待。

備份與還原流程使用合成資料驗證，不讀取個人紀錄，也不進行查票、訂位或取消。
