# 桌面介面與工具分層

2026-10-24 新增 `backend.dualRail` 與 `DualRailDialog.qml`，由「新增行程」及「任務進度」進入。雙鐵執行時納入全域忙碌互斥，關閉等待兩個工作；台鐵仍需人工驗證與未知後續頁面接手，見 [雙鐵說明](dual-rail.md)。

2026-10-23 原始碼更新。本輪先整理介面、架構及操作回饋；依開發決策暫緩製作新安裝包。啟動方式仍為 `python -m thsr_ticket.desktop`。

## 操作變化

2026-10-24 補上常用範本、首頁月曆／待辦與繳費提醒。新服務為 `backend.planner`，原始碼及 QML 責任、提醒限制與保存範圍見 [行程管理](journey-planner.md)；原有防重送與官方核對規則不變。

設定頁現在分為三區：

| 分頁 | 操作 |
| --- | --- |
| 一般偏好 | 啟用任務通知、測試通知、設定 Windows 個資保護。通知偏好立即保存；個資保護仍需按上方「儲存設定」。 |
| 資料管理 | 載入／另存設定、開啟資料夾、展開目前檔案位置、完整備份與還原、進入歷史紀錄整理。 |
| 進階與關於 | 本次診斷匯出、歷史任務診斷、環境檢查、版本及手動更新檢查。 |

通知開啟且系統支援時，「測試通知」才可用。它只送出固定測試文字，點擊回到設定頁，不會載入瀏覽器、查票、訂位或修改訂位狀態。測試不會消耗正式任務的通知次數，也不會改變目前任務。Windows 仍可能依通知或勿擾設定隱藏訊息；「已送出」不代表保證顯示。

設定頁以開關表示布林選項，檔案路徑與搬移說明預設收起。載入設定集中在行程編輯頁與資料管理；上方儲存按鈕在編輯行程或設定有變更時出現。訂位及本機資料操作的必要確認仍保留。

儲存或啟動驗證失敗會切回行程編輯頁，展開需要的進階區塊、捲動到第一個錯誤欄位並聚焦。欄位提供可及名稱與提示；頁籤支援方向鍵，共用按鈕、頁籤及開關顯示鍵盤焦點。這是基礎鍵盤與可及性改善，尚未代表完整螢幕閱讀器或所有輸入法驗收。

## 畫面檔案責任

`Main.qml` 現在負責視窗框架、側欄、頁面切換、共用底列與訊號連接。每個頁面明確接收 `backend`，需要上層開啟對話框時發出訊號，不直接存取別的檔案內部 ID。

| 檔案 | 責任 |
| --- | --- |
| `OverviewPage.qml` | 總覽、旅程卡片及任務入口。 |
| `JourneyPage.qml` | 行程／乘客表單、進階選項與錯誤欄位焦點。 |
| `ProgressPage.qml` | 任務階段、查詢輪數、停止與詳細紀錄。 |
| `BookingsPage.qml` | 訂位篩選、分頁及每筆操作訊號；篩選與分頁狀態留在此頁。 |
| `DatePicker.qml` | 年／月／日滾輪、滑鼠／拖曳／鍵盤選取、閏年與月底調整、取消及套用日期。 |
| `SettingsPage.qml` | 三個設定分頁，按需建立目前分頁內容。 |
| `BookingActions.qml` | 本機封存、人工核對、官網取消引導及其選取狀態。 |
| `StorageDialog.qml` | 執行紀錄、備份及中斷復原；內含各項確認對話框。 |
| `DiagnosticDialog.qml` | 已凍結的診斷預覽及匯出入口。 |
| `UnsavedDialog.qml` | 載入／關閉前的未儲存選擇。 |
| `Caption.qml`、`Line.qml` | 共用輔助文字與分隔線。 |
| `SegmentTab.qml`、`PreferenceSwitch.qml` | 共用頁籤與設定開關，統一選取、停用及焦點樣式。 |

`HistoryDialog.qml`、`Field.qml`、`TaskPanel.qml`、`Card.qml`、`AppButton.qml` 仍各自負責既有的共用畫面。`BookingActions` 開啟核對或取消引導時會清除上次的確認欄位，避免把上一筆選擇帶入下一筆。

日期按鈕開啟三欄年／月／日選擇器，支援上下拖曳、滑鼠滾輪及方向鍵。`Field` 只在日期欄位載入此元件；開啟時讀取目前表單日期，重開時重新對齊。年月改變會保留可用的日期，例如 1 月 31 日改成閏年 2 月時選到 29 日；日欄模型更新後再對齊，避免下一次滾動跳到月初。按套用才送出日期，啟動時間的時分秒由 Field 保留；關閉時停止接收滾輪慣性造成的待選值變更，取消不修改表單。

## Python 分層

`DesktopController` 保留設定及訂位的協調責任：啟停任務、驗證／保存設定、防重送狀態、結果載入、封存及人工核對。欄位錯誤以 `validationFailed(field)` 訊號交給畫面處理；Python 不操作 QML 元件 ID。

完整備份另由 `BackupManager` 處理預覽、檔案選擇與背景工作，透過 `backend.backup` 暴露狀態。controller 的計時器接收結果，忙碌狀態納入全域操作互斥；關閉時取消預覽或等待寫入完成。載入還原設定是明確的獨立動作，仍交由原有設定讀取與防重送流程處理；見 [備份架構](backup.md)。

新的 `DesktopTools` 透過 `backend.tools` 提供診斷、通知偏好、測試通知、環境檢查與手動更新檢查。它擁有自己的事件快照與更新結果佇列，以 `notice` 回傳使用者訊息。正式通知仍由正常桌面入口接到系統匣 adapter；預覽及單元測試不建立實際通知介接。

工具若需要目前任務資訊，會呼叫 controller 提供的唯讀 `tool_context()`，取得設定位置、任務分類、模式、防重送狀態、階段與忙碌狀態。訂位決策仍使用 controller／核心及磁碟狀態，不從工具快照反向恢復任務或放行重送。

controller 的既有計時器輪詢工具更新及歷史讀取結果；背景工作只寫入 queue，再由 Qt 主執行緒更新屬性。更新檢查啟動失敗會解除忙碌狀態；例外原文不進入提示。歷史診斷仍沿用取消、generation 及關閉等待機制。

開發者原先在 controller 呼叫的診斷、通知與更新方法，現在改由 `controller.tools` 呼叫，例如 `controller.tools.prepareDiagnostics()`。CLI 與訂位核心介面未因這次拆分變更。

## 驗證與後續

`test_desktop.py` 保留原有防重送、凍結快照、背景讀取及任務啟停測試，新增測試通知不影響訂位、更新檢查在背景執行、啟動失敗解除忙碌，以及鍵盤切換分頁／進階欄位錯誤聚焦。`scripts.preview_desktop` 用暫存假資料產生五個頁面、三個設定分頁及各對話框圖片。

本輪未製作安裝包。後續原始碼已加入完整備份、永久查票日誌清理、實驗性官網核對／取消及 OCR 標註評估，入口與完成狀態見 [交付確認](optimization-audit.md)。官網核對與取消由獨立 `BookingManager` 保持單一瀏覽器執行緒；清理及 OCR 共用 `LocalJob` 的背景工作與結束等待。歷史列表改為 Python 篩選分頁，每次只傳 25 筆給 QML。

## 搜尋與原生桌面收尾

「我的訂位」在停止輸入 250 毫秒後更新搜尋，按 Enter 或清空立即更新。索引在 `RecordLoader` 背景準備；同一份快照最多快取八組篩選，換頁直接取目前 25 筆。刷新或切換設定會建立新快照，不沿用舊匹配結果。

側欄、搜尋、日期與狀態篩選均提供可存取名稱。喚回視窗使用 QWindow 的 `windowState()`，最小化時還原，一般顯示以 `setVisible(True)` 保留最大化；再次啟動與通知點擊共用此函式。

可用以下工具開啟隔離假資料視窗，驗證實際 Windows Qt 的焦點、鍵盤及縮放；不讀取日常設定或啟動訂位：

```powershell
.\.venv\windows\Scripts\python.exe -m scripts.verify_desktop_session --scale 1 --output build/desktop-session-100.json
.\.venv\windows\Scripts\python.exe -m scripts.verify_desktop_session --scale 1.5 --output build/desktop-session-150.json
```

加 `--send-notification` 會額外送出一次固定文字的本機測試通知。工具自行開關視窗、透過 Qt 注入自己控制項的鍵盤事件；通知回頁路徑以訊號模擬，不會自動點擊系統通知。報告會區分 API 支援、是否要求送出、視窗啟用及待人工觀察項目。100／150% 已通過本機測試，但不能代替螢幕閱讀器朗讀、真實通知點擊或完整人工操作驗收。
