# 開發範圍與驗收狀態

更新日期：2026-10-23。現行發行版本為 0.4.0；歷史診斷、通知、介面分層、完整備份及後續優化均為尚未重新打包的原始碼更新。逐項交付與固定範圍見 [交付確認](optimization-audit.md)。

## 開發方針

依使用者決定，現階段優先完成程式功能、介面及測試，暫緩製作新版安裝包。既有建置腳本與驗收流程留待主要流程定案、準備交付時集中執行。日常開發從原始碼啟動，持續執行離線回歸；不因暫緩打包而省略必要測試。

本輪五項收尾範圍固定；缺陷修正、外部驗收與未來選配分開記錄。完成原始碼交付後，不再把選配功能自動補進待辦，避免每次檢查都重開一批「尚未完成」。

## 目前已完成

- Qt 五個頁面及主要對話框已拆分，Main.qml 負責視窗框架與協調。
- 診斷、通知偏好、測試通知、環境及更新檢查移至 DesktopTools，訂位 controller 保留單一任務與防重送決策。
- 設定改為一般偏好、資料管理、進階與關於三區；開關與頁籤採共用樣式，路徑與次要說明預設收起。
- 驗證失敗會回到行程頁，展開進階區、捲動並聚焦錯誤欄位；基礎方向鍵／焦點操作有離線測試。
- 歷史診斷支援過往任務及歷史備份、受限讀取、版本來源、處理指引與過濾匯出。
- 訂位歷史背景載入、分頁、逐列勾選、掃描容錯、可還原整理與中斷復原均已實作。
- 完整備份可預覽目前設定與關聯紀錄，還原到新的資料夾；保留狀態、原始內容與修改時間，沒有原狀態時新增待核對紀錄。
- 已有實驗性官網核對與未付款單程取消、可設定網路退避、純查票日誌保留／永久清理及 OCR 圖形標註／評估。
- 歷史清單背景建立搜尋索引，以最多 8 組快取重用篩選結果；輸入等待 250 ms，Enter／清空立即套用，QML 每頁僅接收 25 筆。
- 修正行程核對誤用頁尾日期等跨欄位文字的問題；修正 QQuickWindow 喚回 API，保留最大化狀態，補側欄與篩選可存取名稱。
- 真 Windows 的 100／150% 日期滾輪、焦點、喚回與鍵盤檢查通過；最新集中驗證 493 項通過、1 項實站測試跳過，十項瀏覽器測試已執行，Flake8 通過。
- 已提供一鍵集中報告及可操作的隔離假資料視窗；修正批次測試暫存路徑過長，以及 CDP 關閉未完整退出隔離 Chrome 造成暫存占用的問題。
- 依使用者驗收回饋，日期改為可上下滑動的年／月／日三欄滾輪，含閏年、月底、取消／套用及啟動時間保留；其餘介面測試使用者概括回報沒有其他問題。

操作與設計見 [桌面介面分層](desktop-ui.md)、[歷史診斷](history-diagnostics.md)、[紀錄管理](record-storage.md)。

## 本輪收尾與外部驗收

已補集中檢查與隔離假資料視窗。使用者概括回報其他測試沒有問題，本輪已依回饋完成日期滾輪，不要求重做 U2–U7；後續若需重現問題，沿用 [集中驗收清單](acceptance.md) 編號。官網／OCR 的 L1、L2 仍待資料。新增功能測試納入 Windows 必測，所有 scripts 納入該平台 Flake8，避免後續工具更新未檢查。

| 順序 | 工作 | 現況與完成條件 |
| --- | --- | --- |
| 1 | 行程核對缺陷 | 已修正並驗證同一列六欄契約，拒絕頁尾日期、日期數字冒充車次、抵達時間冒充出發時間及不明欄位。 |
| 2 | 官網介接實站驗收 | 真 Chrome 合成流程通過；使用者已回覆沒有測試資料，維持待資料。需指定測試訂位再比對登入後頁面、取消／回查；實驗性標示保留。見 [操作與契約](booking-management.md)。 |
| 3 | OCR 實站資料評估 | GUI 評估已完成；使用者目前沒有人工標註高鐵圖片，維持待資料，不能宣稱實站準確率改善。 |
| 4 | Windows 操作驗收 | 原生 Qt 的 100／150% 喚回、最大化保留、焦點、鍵盤與可存取名稱已驗。通知視覺／實際點擊、完整人工路徑及螢幕閱讀器仍待人工觀察。 |

## 不自動排入待辦的選配

可攜式加密備份、跨帳號自動移轉、自動清理、已付款退票、已取票、來回票與多任務均需另行確認需求。沒有這些選配不代表上述交付沒有完成；不藉放寬目前核對條件直接開放。

## 持續測試及發行前再處理

- 一般 push／PR 已設 Linux 基礎與 Windows Qt 測試，Windows 使用 `--require-desktop` 防止桌面套件缺失被當作通過。每次推送的遠端 CI 結果需獨立確認；本機通過不代表遠端已通過。
- 目前維持單任務；同使用者資料目錄的 Qt 單一實例與同設定操作鎖分工不變。多行程並行、其他證件、會員及來回票仍須另行設計。
- 設定與紀錄已有版本 1 相容契約，未知版本阻擋。未來格式遷移、損壞內容復原及跨帳號保護資料移轉不能自動猜測。
- 主要流程穩定後再更新版本、重建未簽章安裝包、自我檢查、升級／解除安裝及資料保留驗收。現有 0.4.0 的驗收不可代替未發行功能的打包驗收。
- 正式 AppId 的獨立乾淨 Windows 與新版 Qt 官網驗收仍待完成。先驗查票與停止；任何真實訂位／取消都需針對實際操作確認。
- 取得程式碼簽章憑證後再加入正式簽章；自動更新須另設完整性檢查與失敗回復。郵件、通訊服務及關閉視窗後常駐也不屬現有通知功能。
