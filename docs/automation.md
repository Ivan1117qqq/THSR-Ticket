# 定時自動訂位

先設定行程及乘客資料，再啟動程式。到達設定時間後開始查詢，沒有符合條件的車次便依間隔重查；
找到符合條件的車次後自動選車及送出訂位，取得訂位代碼即停止，**不付款**。
目前提供命令列與 JSON 設定檔，尚無圖形設定視窗。

## 使用方式

先依 README 安裝 `requirements-automation-lock.txt`，並安裝 Chrome。
以下指令使用本專案已建立的 `.venv/windows` 環境；自行建立環境時請調整 Python 路徑。

```powershell
Copy-Item booking.example.json booking.local.json
notepad booking.local.json
```

範例中的 2099 年日期和身分證提示文字必須換成你的資料。
`booking.local.json` 是明文個資檔案，已列入 `.gitignore`；若自行改檔名，也請加入忽略清單。

先做離線設定檢查：

```powershell
.\.venv\windows\Scripts\python.exe -m thsr_ticket.main --config booking.local.json --validate-config
```

正式啟動（預設 Chrome 與本機 OCR，不需再加 `--auto-captcha`）：

```powershell
.\.venv\windows\Scripts\python.exe -m thsr_ticket.main --config booking.local.json
```

只想驗證查詢，可加 `--query-only`；同樣遵守啟動時間及次數上限，但找到車次後不選車、不訂位。
可用 `--browser msedge` 選擇 Edge；正式查詢仍建議使用先前實站驗證過的有畫面 Chrome 模式。

## 設定欄位

`booking.example.json` 是空白範本，實際執行讀取的是 `--config` 後指定的檔案，例如 `booking.local.json`。
若你已建立個人設定，直接修改該檔案即可，不要再次複製範本覆蓋它。

最容易混淆的是兩種時間：**`start_at` 是程式何時開始查票；`outbound_date` 加上出發時段，才是你何時搭車。**
例如範本表示「2099 年 1 月 1 日開始查詢，想買 1 月 15 日上午 09:30–12:00 台北到左營的一張成人票」。
2099 年只是示範，不代表網站開放那一天訂票，使用前必須更換。

### 何時開始、多久再查

| 欄位 | 範本值 | 怎麼填 |
| --- | --- | --- |
| `start_at` | `"2099-01-01T00:00:00+08:00"` | 開始查票的日期與時間。`T` 分隔日期和時間，`+08:00` 表示台灣時區；`00:00:00` 為當天凌晨。程式要提前啟動，才會等待這個時間；若時間已過就立即開始。 |
| `interval_seconds` | `0.5` | 查完一輪、沒找到票時，等待 0.5 秒再查。填 `1` 就等一秒；必須大於 0。不是一輪查詢的耗時，也不是訂位次數。 |
| `max_attempts` | `60` | 最多查 60 輪，包含第一輪、OCR 分數不足、驗證碼錯誤及無票重查；不是 60 秒。範圍 1–10000，找到票或發生需停止的錯誤可提早結束。 |
| `ocr_model` | `"standard"` | 使用哪套內建 OCR 模型；可填 `"standard"` 或 `"beta"`。未填時使用 standard，舊設定檔不用修改。beta 不代表保證更準，詳見 [模型評估](ocr-evaluation.md)。 |

例如一輪查詢花 2 秒、間隔填 `0.5`，下一輪約在 2.5 秒後開始。實際耗時依網站與辨識速度而定。

### 要搭哪一天、哪一段路線

| 欄位 | 範本值 | 怎麼填 |
| --- | --- | --- |
| `start_station` | `2` | 上車站的數字代碼，`2` 是台北。 |
| `dest_station` | `12` | 下車站的數字代碼，`12` 是左營；不得和上車站相同。 |
| `outbound_date` | `"2099-01-15"` | 搭車日期，填 `"年-月-日"`，不得早於今天或設定的啟動日期；是否開放訂票仍由網站判定。 |
| `earliest_departure` | `"09:30"` | 最早可接受的發車時間，使用 24 小時制及兩位數格式。 |
| `latest_departure` | `"12:00"` | 最晚可接受的發車時間，包含 12:00 發車的班次；不是抵達時間。不得早於最早出發時間，不支援跨午夜區間。 |
| `train_ids` | `[]` | 不指定車次時保留 `[]`；指定時例如 `[615, 617]`，優先選 0615，再選 0617。JSON 數字不要寫成 `0615`。 |

車站代碼如下，去程或返程方向都使用同一組代碼：

| 代碼 | 車站 | 代碼 | 車站 |
| --- | --- | --- | --- |
| 1 | 南港 | 7 | 台中 |
| 2 | 台北 | 8 | 彰化 |
| 3 | 板橋 | 9 | 雲林 |
| 4 | 桃園 | 10 | 嘉義 |
| 5 | 新竹 | 11 | 台南 |
| 6 | 苗栗 | 12 | 左營 |

車次與時段條件必須**同時符合**。例如 `[615, 617]` 中，0615 若不在指定時段，仍不會選它。
`[]` 表示從網站這次回傳的車次中挑最早符合時段的班次，不是忽略時段，也不代表任意搭乘時間。

### 幾張票、什麼車廂

| 欄位 | 範本值 | 意思 |
| --- | --- | --- |
| `adult_tickets` | `1` | 成人票 1 張。 |
| `child_tickets` | `0` | 孩童票 0 張。 |
| `disabled_tickets` | `0` | 愛心票 0 張。 |
| `elder_tickets` | `0` | 敬老票 0 張。 |
| `college_tickets` | `0` | 大學生票 0 張。 |
| `class_type` | `0` | `0` 為標準車廂，`1` 為商務車廂；不會自動改選另一種車廂。 |

每種票填 0–10 的整數，沒有需要的票種填 `0`，五種票合計必須為 1–10 張。
例如兩位成人同行，把 `adult_tickets` 改為 `2`，其他票種保持 `0`。
票種資格、優惠與可售車廂組合由網站判定；此設定不會保證同行座位相鄰。
自動模式的靠窗／走道偏好沿用網站預設，目前沒有對應 JSON 欄位。

### 訂票人的資料

| 欄位 | 範本值 | 怎麼填 |
| --- | --- | --- |
| `personal_id` | `"請填入身分證字號"` | 換成實際台灣身分證字號，保留雙引號。程式檢查格式，但不驗證身分證檢查碼；目前不支援護照。 |
| `phone_num` | `""` | 手機號碼需加雙引號，格式為 09 開頭的 10 位數，不含空格或連字號。留 `""` 表示不填，實際是否可接受由網站判定。 |

這些是最終訂位使用的資料，不是逐位乘客名單。請只填在自己的 `booking.local.json`，不要填回共用範本。

### JSON 填寫與第一次測試

- 只修改冒號右側的值，左側英文欄位名稱不要改，也不要新增中文說明欄位。
- 日期、時間、證號、手機使用半形雙引號 `"`；票數、車站、間隔填數字，不加引號。
- `train_ids` 使用中括號，例如 `[]` 或 `[615, 617]`。
- 欄位之間用半形逗號隔開，最後一個欄位後不要加逗號。JSON 不支援 `//` 或 `#` 註解。
- 存成 UTF-8。範本中的身分證提示不是有效資料，原樣執行驗證會失敗。

第一次測試可把 `start_at` 設成今天已過的時間、`max_attempts` 設為 `3`、`interval_seconds` 設為 `1`，
乘車日期則填實際想查的有效日期。儲存後先驗證，再只查票：

```powershell
.\.venv\windows\Scripts\python.exe -m thsr_ticket.main --config booking.local.json --validate-config
.\.venv\windows\Scripts\python.exe -m thsr_ticket.main --config booking.local.json --query-only
```

`--validate-config` 只檢查格式與程式規則，不確認開賣日期、有無座位或身分真實性。
`--query-only` 不會送出訂位；移除它才會在找到符合條件的車次後自動訂位。

### 欄位速查

| 欄位 | 說明 |
| --- | --- |
| `start_at` | 開始查詢時間，例如 `2026-10-01T00:00:00+08:00`；未填時區視為台灣時間。已過時間則立即開始。 |
| `interval_seconds` | 上一輪完成後的等待秒數，可填 `1` 或 `0.5` 等正數；不重疊送出請求。 |
| `max_attempts` | 最多查詢次數，預設 60，範圍 1–10000；達上限停止。 |
| `ocr_model` | `"standard"`（預設）或 `"beta"`，使用同一分數門檻，啟動時預載並重用。 |
| `start_station` / `dest_station` | 車站編號：1 南港、2 台北、3 板橋、4 桃園、5 新竹、6 苗栗、7 台中、8 彰化、9 雲林、10 嘉義、11 台南、12 左營。 |
| `outbound_date` | 乘車日期，`YYYY-MM-DD`；是否已開放訂票由網站判定。 |
| `earliest_departure` / `latest_departure` | 同一天可接受的出發時段，`HH:MM`，包含端點。網站查詢時間向下取至支援時段，再依實際車次篩選。 |
| `train_ids` | 可接受的車次優先順序，例如 `[615, 617]`；空陣列表示從回傳結果選最早符合時段的車次。只會選列出的車次，不會自動改選清單外車次。 |
| `adult_tickets` / `child_tickets` / `disabled_tickets` / `elder_tickets` / `college_tickets` | 成人、孩童、愛心、敬老、大學生票數，合計 1–10 張。 |
| `class_type` | `0` 標準車廂、`1` 商務車廂；座位偏好使用網站預設。 |
| `personal_id` / `phone_num` | 台灣身分證字號、手機號碼（可留空）；不支援護照與會員功能。 |

這是「依時間查詢後篩選車次」，不是網站的直接指定車次查詢，也不會自動翻頁搜尋整天的班次。
時間由本機時鐘決定，電腦需保持開機且不要睡眠。瀏覽器與 OCR 模型會先載入等待，第一輪載入網頁、辨識及網站回應仍需時間，
`0.5` 秒不是每秒兩次完成查詢或訂位的保證。

## 停止與重複訂位防護

- 車次表單沒有符合條件的班次、網站回覆明確認得的無車次訊息、OCR 無可靠結果，或網站明確回覆驗證碼錯誤時，自動重查。
  等待 `interval_seconds` 後重新取得首頁、工作階段表單與驗證碼，不重用被拒絕的圖片或表單。
- 重查共用 `max_attempts` 總輪數，沒有固定 3 次上限；最後一輪結束後不再等待或請求。
  OCR 無可靠結果的那一輪不送出查詢，但仍計入輪數。
- 驗證碼錯誤僅接受明確文案「檢測碼輸入錯誤，請確認後重新輸入，謝謝！」或對應的「驗證碼」版本。
  同時出現其他錯誤、HTTP 403／429、未知文案、模型故障、網路失敗或頁面格式改變時停止，不等待鍵盤輸入。
- 驗證碼重試僅作用於車次查詢階段；選車或最終訂位失敗不會因此重送。
- 送出最終訂位前，以獨占方式建立設定檔旁的 `booking.local.state.json`，不記錄身分證或手機。
  成功時保存訂位代碼；逾時、解析失敗或中斷時保留待確認紀錄。再次使用同一設定檔訂位會停止。
- 若有上述紀錄，先在官網查詢是否已訂位。確認後才由你自行封存或移除紀錄；程式不自動清除。
  防護以同一設定檔路徑為範圍，勿用複製設定檔的方式同時執行相同行程。
- `Ctrl+C` 可中止等待或執行；若已送出最終訂位，仍需確認官網狀態。

## 結果與執行紀錄

不需新增設定欄位。自動模式開始查詢後，會在設定檔旁建立以下資料：

```text
booking.local.json
booking.local.state.json
booking.local.runs/
  <每次執行的獨立代碼>/
    events.jsonl
    result.json
```

每次執行建立不同資料夾，舊紀錄不被覆蓋。若使用不同設定檔名稱，資料夾也會跟著改名。
這項保存功能目前適用 `--config` 自動模式，不包含互動訂票流程。

### 完整訂位結果：result.json

只有成功解析訂位結果後才建立，包含：

| 欄位 | 說明 |
| --- | --- |
| `saved_at` | 保存時間，含台灣時區 |
| `status` / `payment_status` | `booked` / `unpaid`，表示當次已訂位、尚未付款；後續不會自動同步官網付款或取消狀態 |
| `requested_outbound_date` | 設定檔指定的完整乘車日期 |
| `tickets` | 網站回傳並成功解析的訂位結果清單 |
| `tickets[].id` | 訂位代碼 |
| `tickets[].date` | 網站顯示的乘車日期，保留原文字，不自行推算年份 |
| `tickets[].start_station` / `dest_station` | 起訖站 |
| `tickets[].train_id` | 車次 |
| `tickets[].depart_time` / `arrival_time` | 發車及抵達時間 |
| `tickets[].seat` / `seat_class` | 車廂座位及車廂種類 |
| `tickets[].price` / `ticket_num_info` | 金額與票種張數文字 |
| `tickets[].payment_deadline` | 網站顯示的繳費期限，保留原文字 |

終端會印出完整檔案位置，可直接在編輯器開啟。查詢模式、無票結束或訂位結果不明時，不建立成功結果檔。
舊版本已完成的訂位不會自動補回完整結果；請保留先前的終端資訊或至官網查詢。

### 每輪執行紀錄：events.jsonl

每行是一筆獨立 JSON 事件，使用台灣時區時間。可直接用文字編輯器閱讀。

| 事件／結果 | 意義 |
| --- | --- |
| `run_started` | 本次查詢開始，含模型、間隔、次數上限及是否只查詢 |
| `stage` | `homepage` 首頁、`captcha_image` 圖片、`ocr` 辨識、`query` 查詢、`select_train` 選車、`submit_ticket` 最終送出，各自的耗時與是否完成 |
| `ocr` | 是否產生可接受候選及模型分數，不保存辨識文字；分數不是準確率 |
| `attempt_finished` | 每輪結果：`ocr_no_candidate`、`captcha_rejected`、`no_matching_train`、`query_match` 或 `booked`；異常時也會記錄停止分類 |
| `run_stopped` | 非正常停止，含發生階段與分類，例如 `network_timeout`、`network_error`、`http_error`、`website_rejected`、`ocr_unavailable`、`booking_unconfirmed` 或 `interrupted` |
| `run_finished` | 成功完成，或達到次數上限 |
| `result_save_failed` / `state_update_failed` | 已成功訂位，但完整結果或防重送狀態更新失敗 |

`elapsed_ms` 單位為毫秒。每輪耗時不含輪次之間的等待；整次執行耗時包含重試等待，但不含啟動前的排程等待、瀏覽器啟動或模型預載。
網路錯誤分類依傳輸層提供的例外：瀏覽器包裝為一般連線失敗的逾時會列為 `network_error`。
`stage` 的 completed 只表示該呼叫正常回傳，網站是否接受仍需看後續事件。

可列出最近的紀錄：

```powershell
Get-ChildItem .\booking.local.runs -Recurse -File | Sort-Object LastWriteTime -Descending
```

### 資料與存檔失敗

- 執行紀錄不保存身分證、手機、驗證碼、訂位代碼、網站原始 HTML、表單或原始錯誤文字；完整結果檔包含訂位代碼與行程，不含證號、手機、驗證碼。
- `*.runs/` 已加入 Git 忽略。這些檔案是本機明文，完整結果仍應自行保管。
- 成功訂位先顯示終端結果，再保存檔案；若寫入失敗，會提醒保留終端資訊，不因紀錄問題重新訂位。
- 狀態檔更新使用暫存檔替換，更新失敗時保留原防重送紀錄。執行紀錄無法寫入只提醒一次，後續停止記錄。
- `--validate-config` 不產生執行紀錄。紀錄從實際進入自動流程開始，不記錄設定錯誤、排程等待期間中斷或啟動失敗。

## 查看、封存與準備下一筆

查看目前的防重送狀態、完整行程與已封存紀錄：

```powershell
.\.venv\windows\Scripts\python.exe -m thsr_ticket.main --config booking.local.json --show-bookings
```

這個指令只根據 `--config` 的路徑定位紀錄，不讀取設定檔中的個資或驗證乘車日期，因此過期行程仍可查看。
紀錄顯示的是當時保存的資料，不會查詢官網的即時付款、取消或車次狀態。
舊版只有狀態檔時，會顯示訂位代碼，無法自行補出完整行程。損壞的結果檔會提示並略過，不刪除。

確認要保留原紀錄並準備下一筆時，用**目前狀態檔中的訂位代碼**確認封存：

```powershell
# YOUR_CODE 是佔位文字，請換成查看指令顯示的代碼
.\.venv\windows\Scripts\python.exe -m thsr_ticket.main --config booking.local.json --archive-booking YOUR_CODE
```

封存後：

1. 原 `booking.local.state.json` 移至 `booking.local.runs/archives/<獨立封存代碼>/state.json`，內容原樣保存。
2. 各次執行的 `result.json` 與 `events.jsonl` 留在原處，仍可用查看指令閱讀結果。
3. 原防重送阻擋解除，但程式不會接著訂票；你需要先更新行程，再自行啟動。

封存不是取消或付款，官網原訂位仍然存在。尚未確認結果的 `submission_pending`、未知狀態、
無有效代碼或損壞紀錄一律不自動封存；請先確認官網訂位及程式是否仍在執行，再人工處理。
代碼不符或檔案移動失敗時，原紀錄仍保留。

封存指令以 `.archive.lock` 避免同時封存，正常結束時移除鎖檔。若封存程序被強制終止而遺留鎖檔，
確認沒有其他封存程序執行後才可人工移除；不要在訂位程式仍執行時封存紀錄。
封存檔位於已被 Git 忽略的 `*.runs/` 中，鎖檔也已加入忽略清單。
