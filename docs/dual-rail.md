# 高鐵與台鐵同時訂票

2026-10-24 原始碼功能。使用者選定的策略是 **兩邊各取得一筆訂位後，各自停止；不付款**。其中一邊失敗、無位或成功，均不停止另一邊；不用的車票由使用者自行至官網取消。

## 使用方式

在目前專案工作區啟動最新原始碼（舊 EXE 不包含本輪功能）：

```powershell
cd E:\NTUST\NTUST_Institute\Project\THSR-Ticket
.\.venv\windows\Scripts\python.exe -m thsr_ticket.desktop
```

已使用本專案桌面環境時不用重建虛擬環境；若換了電腦，先依 README 安裝桌面與自動化依賴及 Chrome。

1. 在「新增行程」完成原有高鐵設定，包含日期、啟動時間、乘客與證件。
2. 按「雙鐵同時訂票」，選擇台鐵自己的起訖站、一般座票數、時段或最多三個偏好車次。高鐵和台鐵站別獨立，例如高鐵左營不能直接視為台鐵高雄。
3. 可先按「儲存台鐵設定」。台鐵設定不保存證件，日期、啟動時間與身分證使用高鐵表單；啟動時會凍結同一份設定供兩邊使用。
4. 第一次建議先按 **「預填檢查 · 不訂位」**：只開台鐵 Chrome、預填內容，不會自動送出；台鐵訂位 POST（含 AJAX）也會阻擋。完成檢查後按停止。此模式仍會建立沒有個資的執行紀錄，並使用正常設定驗證及既有台鐵紀錄預檢。
5. 只想測台鐵時按 **「只啟動台鐵」**，不啟動高鐵，也不要求清除高鐵既有紀錄；台鐵既有紀錄仍會阻擋重跑。此按鈕是正式訂位嘗試，會到指定時間送出，並非只查票。要同時執行才選「雙鐵同時啟動 · 不付款」，兩個背景執行緒會分別開啟獨立 Chrome。
6. **台鐵目前是實驗性的輔助訂票。** 如官網要求真人驗證、選車、優惠票種或後續確認，請在程式開啟的台鐵 Chrome 接手；可按台鐵工作卡的 **「顯示視窗」** 切回該視窗，最小化時嘗試還原。程式不會代解 Google 驗證，也不會猜按未知的下一步按鈕。雙鐵模式下高鐵繼續使用既有自動訂位流程。
7. 關閉面板不會停止工作；可由「新增行程」重新開啟，或從「任務進度」查看雙鐵工作。支援分別停止一邊或全部停止；關閉 App 會停止並等待兩個工作釋放。

台鐵時段下拉選單只提供官網的整點、半點及 23:59；指定車次時採官網「依車次」訂票，否則採「依時段」並勾選官網提供的全部對號車種。其他座位偏好沿用官網預設。一般座票數與高鐵各票種張數獨立，不會自動把高鐵大學生票等條件轉成台鐵優惠。

## 重查與結果核對

- 台鐵僅在同一訂票表單的明確無位錯誤中重查，依台鐵設定的間隔與輪數上限執行。驗證失敗、未知頁面及網路錯誤不會被誤判成無位而反覆送出。
- 首頁連線暫時失敗且尚無送出紀錄時，預設最多連線 3 次，以 3、6 秒等退避等待，最長 30 秒；可在進階設定調整「送出前連線失敗上限」及「連線退避上限」。網站 403／429 拒絕或表單變更不自動重試；送出後斷線一律保留待核對狀態。
- 官網公告視窗由你閱讀並關閉，程式等待後繼續預填，不替你同意公告。公告關閉回報與官方驗證 POST 不屬於訂票送出，不會建立假性的待核對訂位紀錄。
- 官網主頁導覽 POST 在離開瀏覽器前會先寫入待核對紀錄；保存失敗就阻擋該次送出。這也涵蓋在台鐵 Chrome 中由使用者點擊的後續導覽 POST。
- 自動判定成功需同時具有明確成功標題、具名訂票代碼，以及同一行程列的完整日期與兩站。沒有實站成功樣本時，不保證目前所有官網版型都能自動辨識；不符契約就保留待核對狀態。
- 台鐵 Chrome 等候接手時仍會繼續監看頁面。請先在 Chrome 完成必要流程，再停止工作；停止／關閉會關閉程式開啟的該台鐵瀏覽器。
- 若已在官網成功但程式未辨識，先停止台鐵工作並到官網查詢，再在雙鐵面板勾選「我已在台鐵官網確認這筆訂位狀態」，輸入訂票代碼並按「保存核對結果」。這是使用者確認的本機登記，不會發送新訂位。
- 台鐵訂票代碼預設遮蔽，可按眼睛顯示或按「複製代碼」。若讀到代碼但狀態檔更新失敗，會在面板保留尚未存檔的代碼並提示；請立即複製、核對官網並保存人工核對結果，關閉 App 後無法保證保留這份記憶體中的代碼。代碼不會寫入一般進度日誌。
- 高鐵結果仍在「我的訂位」；台鐵目前結果在雙鐵面板，另一邊仍執行時也會更新。可展開「顯示本次進度紀錄」，或按「開啟台鐵執行紀錄」查看這次失敗分類與退避紀錄。
- 要準備下一次台鐵訂票，核對官網後勾選確認、按「封存本機紀錄」，再確認封存。**本機封存不會取消官網訂位**，也不會替你選擇取消哪一張票。

已有任何一邊的送出／成功紀錄時，**雙鐵**啟動預檢會阻擋兩邊，避免只清除其中一邊後誤訂重複車票。「只啟動台鐵」略過高鐵的訂位紀錄預檢，仍需有效主表單與台鐵無既有紀錄；不刪除、不改寫高鐵防重送狀態。高鐵沿用既有紀錄管理；台鐵使用獨立紀錄。結果不明時請不要刪除狀態檔重跑。

## 架構與保存

| 檔案 | 責任 |
| --- | --- |
| `thsr_ticket/dual_rail.py` | 兩個獨立工作、各自停止訊號、狀態佇列與高鐵既有 worker 的訊息介接。 |
| `thsr_ticket/tra_booking.py` | 台鐵設定驗證、官網表單控制、POST 前保存、防重送、保守結果解析與本機封存。 |
| `thsr_ticket/configs/tra_stations.json` | 2026-10-24 從台鐵公開訂票表單擷取的 132 個可選車站及官網輸入值；不使用高鐵站碼。 |
| `thsr_ticket/desktop/dual_rail.py` | Qt 設定與進度橋接、啟動預檢、人工結果登記、封存與關閉等待。 |
| `thsr_ticket/desktop/qml/DualRailDialog.qml` | 台鐵備案表單、雙鐵工作卡、停止、遮蔽代碼與確認操作。 |

台鐵資料集中在 App 資料夾（一般 Windows 為 `%LOCALAPPDATA%\THSRTicket\TravelDesk`），與高鐵目前設定檔位置獨立：

| 資料 | 內容 |
| --- | --- |
| `dual-rail.preferences.json` | 版本 1、台鐵站別／張數／時段／車次／重查偏好，不含證件、手機。 |
| `tra-booking.local.state.json` | 版本 1、營運商、工作識別碼、日期、路線、張數、pending／booked 與已知訂票代碼；不含身分證。 |
| `tra-booking.history/*.json` | 經明確確認後封存的原始紀錄；不改寫官網訂位。 |
| `tra-booking.local.runs/<識別碼>/events.jsonl` | 固定事件、階段、失敗分類與退避秒數；不含證件、訂票代碼、網站原文或驗證碼。 |

以上台鐵資料尚未納入高鐵單一設定的「完整備份」及高鐵月曆／搜尋／繳費提醒。台鐵付款期限以官網為準。需要備份台鐵資料時，關閉 App 後備份以上檔案及資料夾；切換高鐵設定也不會繞過台鐵目前紀錄。

台鐵偏好仍為版本 1，舊檔缺少新增連線設定時補上預設值；未知版本、損壞內容與連結檔保留，不會覆寫。App 開啟後若檔案變成未知版本，儲存時也會阻擋。

## 驗證邊界

自動測試用合成資料驗證真並行、互不停止、預檢、POST 先存再送、保存失敗阻擋、無位重查、結果不明保留、人工核對、封存及 Qt 操作；Chrome 網路全部攔截，不操作真實訂位。U11 為介面操作驗收，L3 為台鐵實站流程驗收；尚未宣稱台鐵可全程無人介入，也未測得真實搶票成功率。

官方來源：[目前個人訂票入口](https://www.railway.gov.tw/tra-tip-web/tip/tip001/tip121/query)、[網路購票規則與驗證說明](https://www.railway.gov.tw/tra-tip-web/tip/tip00C/tipC21/view?lang=zh_TW&proCode=8ae4cac3756b7b41017572e5974c178b&subCode=8ae4cac3756b7b41017573dba4e4186f)。訂票首頁僅作唯讀欄位核對；沒有送出真實訂票或取得測試票。
