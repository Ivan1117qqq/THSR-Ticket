# 集中驗收清單

2026-10-23 原始碼。這份清單集中列出需要使用者觀察的項目；程式可自行驗證的部分由批次工具先執行。U1–U7 可使用假資料完成；L1、L2 目前缺少測試資料，維持待驗收，不需要為了本輪交付臨時建立真實訂位。

## 使用者回饋與本輪修正

使用者回覆「其他測試應該都沒問題」，並要求日期可選年、月、日與上下滑動。本輪依此改成三欄滾輪，補上閏年／月底、重新對齊、取消及保留啟動時分秒的檢查。其餘項目記錄為使用者概括回報沒有其他問題，不要求重做 U2–U7；這個回覆不作為官網與真實 OCR 已驗收的證據。先前自動報告保留當時的人工狀態，不回填成未曾記錄的逐項通過。

## 開始前：自動檢查與驗收視窗

在專案根目錄執行集中檢查：

```powershell
.\.venv\windows\Scripts\python.exe -m scripts.verify_acceptance --native
```

會依序執行 Flake8、完整 pytest 與十項瀏覽器測試、四種官網合成情境、Qt／兩套 OCR 載入／Playwright／Windows 個資保護自我檢查、搜尋量測、100／150% 畫面預覽、原生鍵盤／焦點及驗收視窗檢查。瀏覽器請求由測試攔截；不加 `--live`，不建立或取消真實訂位。過程會短暫出現隔離 Chrome 及測試視窗；不自動送出系統通知。

每次建立新的 `build/acceptance/<台灣時間與識別碼>/`，包含 `report.json`、`summary.md`、各項日誌／產物及 `review-data/`。必要報告遺失、無法解析、出現非預期跳過、執行中修改原始碼或任一步失敗時，整體不會標成通過。只允許既有唯讀實站測試因未開 `--live` 跳過。自動通過不會把 U1–U7 或 L1、L2 改成通過。

最新本機批次為 `build/acceptance/20261023-170352-1eaab2ed/`，十項檢查全部通過，pytest 493 通過／1 項實站跳過，包含新增的 13 項日期回歸。pytest 使用另一個新建的短路徑 `build/qa-<識別碼>/`，避免巢狀備份樣本超過 Windows 路徑限制；路徑會記在報告中。一般不需重新執行自動檢查，直接開驗收視窗即可。

接著開啟可自行操作的驗收視窗：

```powershell
.\.venv\windows\Scripts\python.exe -m scripts.review_desktop
```

視窗標題為「假資料驗收（不會查票或訂位）」。程式自動產生一份新的資料夾並輸出位置，不載入日常 AppData 的設定或最後使用路徑。查票、訂位及官網操作會阻擋；管理瀏覽器工廠亦停用。載入及設定儲存只接受本次假資料資料夾內的位置。

要沿用某次集中報告內的資料，可加 `--data '<該次報告資料夾>\review-data'`。新資料夾不可覆寫既有目錄；需要重做全部操作時，直接重新執行不帶 `--data` 的指令取得全新假資料。

| 子資料夾 | 內容 | 用途 |
| --- | --- | --- |
| `booked` | 目前代碼 `DEMO0001`，另有 30 筆歷史，合計 31 筆。 | 搜尋、分頁、複製及本機封存。 |
| `pending` | 一筆結果待確認狀態。 | 必要確認與處理待確認介面。 |
| `backup` | 獨立已訂位副本，不受 booked 封存影響。 | 完整備份與還原。 |
| `logs` | 三筆修改時間為 2000 年、已結束的純查票日誌。 | 整理、還原及永久清理。 |

每個子資料夾都有 `booking.local.json`；用「新增行程 → 載入設定」或「設定 → 資料管理 → 載入設定」切換。切換時若出現未儲存提醒，可捨棄驗收中的表單變更。代碼與證號均為假資料，證號刻意不通過正式訂票驗證；所有官網確認勾選只在這份假資料中模擬，不能用此結果推斷實際票券狀態。

## 這次集中操作的七項

預估約 20–30 分鐘，依個人操作與輔助工具而異。逐項填「通過／失敗／環境阻擋」；有問題時記編號及重現步驟即可。

### U1：版面、縮放與欄位操作

1. 使用最小視窗，逐一查看五個頁面與三個設定分頁；確認文字可讀、按鈕不重疊，內容超出時可捲動到最後一個操作。
2. 到「新增行程」，測試證號眼睛顯示／隱藏、日期選擇、時間選擇及票數加減。日期視窗可分別上下拖曳年／月／日，亦可用滾輪及方向鍵；切換到 2 月時會調整有效日期。「套用日期」才寫回，取消不修改，啟動日期保留原時分秒。確認切換遮蔽不改變原值。
3. 在進階設定把查詢輪數改成 `0` 再儲存，確認出現錯誤、展開並聚焦對應欄位，沒有啟動任務；改回 `60`。假證號維持無效，這裡不需要儲存成可訂票設定。
4. 關閉後以 `python -m scripts.review_desktop --scale 1.5` 重開一份 150% 假資料視窗，檢查相同的版面與底部操作；不必重新做全部驗收。

**通過條件：** 常用縮放可閱讀及操作，遮蔽與選擇器正確，非法輪數有可理解回饋。縮放及焦點的程式檢查已自動執行，這裡補人的觀察。

### U2：搜尋、分頁、複製與本機封存

1. 載入 `booked/booking.local.json`，到「我的訂位」。預設只看到目前的 `DEMO0001`。
2. 勾「包含歷史紀錄」，確認共 31 筆、兩頁，第一頁最多 25 張、第二頁六張。
3. 搜尋 `DEMO0031`，應只剩一筆；試按 Enter 與清空，再試日期／狀態篩選。
4. 複製 `DEMO0001`，貼到自己的文字編輯器確認正確。按「移至歷史」先取消，確認目前卡片仍在；再開啟並確認封存。
5. 確認目前卡片消失，勾包含歷史仍查得到 `DEMO0001`；沒有操作官網。

**通過條件：** 清單與篩選正確，互動順暢，封存可取消且只改本機紀錄。

### U3：待確認狀態與確認門檻

1. 載入 `pending/booking.local.json`，確認狀態為結果待確認，訂位入口不能直接重新送出。
2. 開啟「處理待確認」，未選結果／未勾確認時，提交按鈕應停用；先返回，確認狀態保留。
3. 再開啟，針對這份假資料選「確認沒有成立訂位」並勾選確認，提交後確認原狀態移至歷史。

**通過條件：** 未完成確認不能解除阻擋，返回不改紀錄，明確確認才封存。真實斷線後不能直接套用此假資料結論，需走 L1 的官網回查。

### U4：完整備份與還原

1. 載入 `backup/booking.local.json`。到「設定 → 資料管理 → 完整備份與還原」，預覽資料，確認包含設定與原防重送狀態。
2. 在本次假資料根目錄備份成新 `*.thsr-backup.zip`，再到還原分頁選它。
3. 還原父資料夾也選本次假資料根目錄；確認預覽顯示新的 `TravelDesk-Restored-...` 子資料夾，不合併原目錄。
4. 確認還原、載入還原設定，確認仍顯示 `DEMO0001` 與已訂位阻擋；原 backup 資料仍在。

**通過條件：** 完成流程不要求編輯 JSON；主要按鈕可見；還原保留原訂位阻擋且不自動訂票。驗收視窗只接受根目錄內的還原設定，因此請依上述位置選擇。

### U5：歷史整理、還原與永久清理

1. 載入 `logs/booking.local.json`，開啟「設定 → 資料管理 → 開啟資料管理」。應可處理三筆日誌。
2. 只選一筆移至歷史備份，確認可從備份分頁還原；還原後三筆均可再掃描到。
3. 返回設定，開啟「保留期限與永久清理」，以 90 天預覽，應有三筆。未勾同意時不能永久刪除。
4. 確認後清除這三筆假日誌，再預覽應沒有可刪項目；清理稽核仍保留。

**通過條件：** 清單、筆數及確認回饋清楚；整理可還原，永久刪除有獨立同意，不會誤稱兩者相同。

### U6：系統通知與視窗喚回

1. 到「設定 → 一般偏好」啟用通知，按「測試通知」並將視窗最小化。
2. 確認 Windows 實際顯示固定測試通知，點擊後回到此驗收視窗的設定頁。
3. 最大化後再次操作通知，確認沒有意外縮回一般視窗；關閉通知偏好後，測試按鈕停用。

**通過條件：** 你實際看見並點擊通知，視窗及頁面正確。若 Windows 通知／勿擾設定阻擋，記「環境阻擋」並附設定狀態，不以「已送出」代替看見通知。

### U7：完整鍵盤與螢幕閱讀器

1. 用 Tab、Shift+Tab、Space、Enter 操作側欄、表單、篩選、頁籤與對話框；確認焦點可辨識、順序合理、能返回。
2. 用系統螢幕閱讀器確認側欄、欄位、眼睛、日期／時間及票數加減有可理解的名稱，能知道目前選取及錯誤狀態。

**通過條件：** 主要路徑可由鍵盤完成，朗讀能理解操作目的。沒有使用螢幕閱讀器時，該子項保留未驗，不以可存取名稱的程式測試代替。

## 等有資料再驗的兩項

| 編號 | 所需資料 | 驗收順序與通過條件 |
| --- | --- | --- |
| L1 | 指定可供測試的訂位、操作範圍及本機保存的取票識別碼。 | 用正常程式先驗只查票／停止，再核對既有代碼、日期、方向、車次及狀態；確認解析契約後，才驗已指定未付款票的取消與重新查詢。斷線不能重送或自行解除防重送。不得在假資料視窗執行；詳見 [官網核對與取消](booking-management.md)。 |
| L2 | 獨立人工核對的高鐵圖片資料夾。 | 同一批資料／門檻評估兩模型，保存資料集識別、樣本數、整串正確率、接受率與延遲；再決定是否更換模型。詳見 [OCR 評估](ocr-evaluation.md)。 |

目前你已回覆沒有這兩種資料，所以維持「待資料」，不妨礙先完成 U1–U7。安裝包依既定決定暫緩，不列入這次驗收。

## 一次回報格式

複製以下格式，通過的填「通過」；失敗項目補上步驟、預期與實際結果。截圖若包含真實證號、手機或代碼，分享前先遮蔽。

```text
使用的集中報告資料夾：
Windows 縮放／驗收視窗 scale：
U1 版面與欄位：
U2 搜尋與本機封存：
U3 待確認：
U4 完整備份與還原：
U5 整理與清理：
U6 通知實際點擊：
U7 鍵盤／螢幕閱讀器：
L1 官網：待資料
L2 OCR：待資料

有問題的項目編號：
重現步驟：
預期結果：
實際結果：
```

`report.json`／`summary.md` 保留自動檢查當時的證據；人工結果使用這份回報記錄，不會因重跑自動測試而被誤改成通過。
