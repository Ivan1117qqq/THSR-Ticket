# 常用行程、繳費提醒與月曆

2026-10-24 原始碼功能；啟動 `python -m thsr_ticket.desktop` 即可使用，尚未重新打包。

## 常用行程範本

從「旅程總覽」或「新增行程」按 **常用行程範本**：

1. 先在行程表單設定路線、時段、車廂、票種與查詢偏好。
2. 開啟範本視窗，輸入名稱，按「從目前行程新增」。不需要填證號才能保存範本。
3. 選取左側範本可預覽路線與票種；「套用範本」會返回行程表單，接著確認本次日期與啟動時間。
4. 支援重新命名、複製、以目前行程更新，以及確認後移除。最多 50 個、名稱 1–40 字，同名會阻擋。

範本只儲存起訖站、車廂、最早／最晚出發、偏好車次、五種票數、OCR 模型、重查間隔、輪數及網路退避。**不儲存搭車日期、啟動時間、證號、手機、訂位代碼或結果。**

套用會取代目前表單中上述偏好，保留其餘欄位與設定檔位置；不會儲存設定、啟動查票、建立新訂位、刪除狀態或放行防重送。執行任務或其他互斥操作期間，範本寫入／套用均停用。表單原有未保存的偏好會被套用內容取代，日期及訂票人仍保留。

## 首頁月曆與待辦

首頁顯示「繳費待辦、待核對、即將出發」三個統計，以及月曆和待辦卡片。範圍是 **目前設定檔及其本機歷史**，不是所有設定檔，也不是官網即時狀態。

- 月曆週一開始，提供上／下月與今天；點月份標題可用年月日滾輪直接跳到指定日期。日期下方的圓點表示有本機行程，點選後列出當日最多 8 筆及總筆數；完整紀錄仍在「我的訂位」。
- 日期必須含完整年份；只有 `MM/DD` 時，需與紀錄保存的完整搭車日期一致才可使用。不根據今天猜年份，跨年也採相同規則。
- 待核對包含目前結果不明或無法讀取的紀錄；不會把它計為已訂位的「即將出發」。
- 繳費待辦包括目前已訂位且未保存已付款／已取票狀態的本機紀錄，**不代表已從官網證明尚未付款**。已確認付款或取消會排除；過期只提示核對，不自動取消或刪除。
- 歷史紀錄可在月曆顯示未來行程；單純本機封存不證明取消。沒有明確未付款證據的歷史紀錄不自動建立繳費提醒。
- 待辦最多顯示 6 筆，優先列待核對，再依期限排序。資料重新整理後才會反映外部變更，首頁可從「我的訂位 → 重新整理」更新。

## 繳費期限提醒

到「設定 → 一般偏好」，先啟用 **桌面通知**，再啟用 **繳費期限提醒**，選擇提前 1 小時、3 小時或 1 天。兩者預設關閉，偏好立即保存。

提醒每分鐘檢查，限 App 開啟、系統支援桌面通知且紀錄已完成讀取時執行。只提醒未來行程中仍需核對付款的紀錄。期限必須有完整年月日及時刻，例如 `2099-01-14 12:00`；無時區時採台灣時間，明確時區則換算成台灣時間。`01/14`、`01/14 12:00`、只有日期或無效日期均不自動排程，不猜年份或當天最後一刻。

若原紀錄只有不完整期限，可在首頁待辦按 **設定提醒期限**：

1. 到官網核對實際完整期限。
2. 在視窗輸入 `YYYY-MM-DD HH:MM`；「選日期」可使用年月日滾輪，再補上時間。
3. 勾選「我已核對官網完整期限」，按保存。只能設定未來且不晚於已知出發時間的期限。

這是本機提醒資料，**不會修改或延長官網期限**，也不會標記已付款、清除防重送或發送付款。可移除手動期限，恢復採用原紀錄中的明確期限。

同一份設定、同一筆行程、同一期限及提前時間只通知一次，發送紀錄會跨 App 重開保留。變更提前時間或手動期限可產生新的提醒。逾期時首頁顯示「已過本機期限，請核對」，不在重開後補發過期通知。通知只含固定提示文字，點擊返回總覽，不包含證號、手機或訂位代碼。

**關閉 App、Windows 睡眠或系統勿擾可能使提醒錯過；它不是背景常駐或保證送達服務。** 不支援通知時仍可使用首頁待辦。若提醒紀錄損壞或無法保存，停止通知並保留原檔，避免反覆發送；不影響既有訂位。

## 保存位置與備份範圍

資料位於 App 資料夾，日常桌面預設為 `%LOCALAPPDATA%\THSRTicket\TravelDesk`；測試與隔離驗收各自使用自己的資料夾。

| 檔案 | 內容 |
| --- | --- |
| `journey-templates.json` | 版本 1、範本識別碼、名稱及允許的非個資欄位。 |
| `journey-reminders.json` | 版本 1、手動期限與發送紀錄，以設定位置和行程的雜湊識別，沒有原始證號／手機／訂位代碼。 |
| `preferences.json` | 沿用原偏好，新增 `payment_reminders`、`payment_reminder_minutes`。 |

上述是 App 全域資料，**目前「完整備份」仍只封裝選定設定及其關聯訂位／日誌**，不包含全域範本、提醒及一般偏好；搬移到新設定位置也不自動套用舊位置的手動期限。需要保留這些全域資料時，關閉 App 後額外備份上述三檔。原檔損壞時不以空白資料覆寫，未知版本亦保留。

## 程式架構

- `journey_templates.py` 定義可保存欄位及有效範圍，處理非個資範本的版本、名稱、數量、讀取大小、損壞保留與原子寫入。
- `journey_planning.py` 是純 Python：解析明確日期／期限、分類紀錄、建立日期索引、產生固定 42 格月曆及有上限的待辦。
- `RecordLoader` 在原背景執行緒準備 `PlanningIndex`，與搜尋索引一起交接；取消和過期 generation 規則不變。QML 不接收完整紀錄做月曆運算。
- `desktop/planner.py` 提供 Qt 屬性與指令，協調全域偏好、手動期限、跨重開去重及通知。紀錄快照由 controller 提供；它不呼叫訂位／取消 API。
- controller 僅連接套用訊號、背景索引及既有通知管線；所有範本更動仍受現有忙碌狀態約束。提醒只作通知，不影響訂位工作決策。
- `TemplateDialog`、`DeadlineDialog`、`JourneyCalendar`、`AgendaCard` 分別負責範本、期限確認、月曆與待辦畫面，透過訊號交由主視窗開啟對話框。
